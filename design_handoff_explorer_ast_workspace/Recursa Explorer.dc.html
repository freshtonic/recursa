Recursa Explorer AST render study · four directions

The AST panel's real problem is not the tree. It is the depth tax.

In the current model every level of user-visible nesting costs three or four tree levels: an enum Value node, its variant element, the concrete node, then the element that holds the children. {"items":[true,null,{"name":"café"}],"ok":true} is 34 occurrence rows and 18 levels of indent. At thousands of nodes the indent runs off the panel before the structure is legible.

So the load-bearing idea in all four options below is chain folding: any run of single-child occurrences collapses into one typographic line — Value::Object › object › Object › members — which takes those 34 rows to 12 and 18 levels to 4, while every name, variant, role and cardinality stays on screen. Nothing is hidden; the chain is just set on one line instead of four. Toggle it live in 1a.
