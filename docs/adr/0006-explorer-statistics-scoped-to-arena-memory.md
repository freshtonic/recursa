# Scope Explorer parse-memory statistics to arena-backed documents

Status: accepted

## Context

The redesigned Explorer UI wants a "concrete AST memory usage" figure alongside
parse timing. An `ExplorerDocument` is backed by one of two things: an ordinary
owned Nested AST (`TypedDocument`), or a bumpalo-arena-backed Flat AST
(`ArenaTypedDocument`). Only the arena case has a cheap, accurate memory
number available (`Bump::allocated_bytes()`); reporting a comparable figure
for a Nested AST would need a new per-type "measure yourself" capability
generated by `recursa-codegen` for every authored root — a materially larger
feature than a statistics call.

## Decision

Add `Adapter::parse_with_statistics`, gated by a new `statistics` feature
(`explorer` now depends on it), returning `ParseStatistics { elapsed,
memory_bytes: Option<usize> }`. `memory_bytes` is `Some` only when the
document is arena-backed; Nested-AST documents always report `None`. No
attempt is made to make memory reporting uniform across both construction
backends.

## Consequences

Explorer UI must treat `memory_bytes` as optional and degrade gracefully
(hide or gray the field) for grammars using the Nested-AST construction
backend. Uniform memory reporting across both backends remains open future
work, not something this decision defers by half-measure.
