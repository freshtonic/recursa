# M3 acceptance contract

This matrix is the normative milestone acceptance contract for the M3 build analyzer. Every row has a stable ID, traces to its originating decision, names executable evidence, and is required to remain green. `Green` means the named evidence passes on the checked-in source and reviewed expectations; it is not a waiver or an intent marker.

The six representative source fixtures are Rust 2024 inputs transformed from `recursa-spike` revision `b410d2f123cd7510a8a40e9e5b971936a2fd8463`. Their comments identify the exact description and grammar source files. Fixed-token wrappers become positional `#[tok(...)]` syntax or presence nodes, regex-backed token types retain matched text, and contextual keywords become concrete kinds admitted by parser targets. No M4 publication or loader behavior is accepted here.

The M3-DIAG-003 checker parses each cited `#[test]` function and checks the exact diagnostic code literals in its asserted output. A source file containing a code or an unrelated test symbol is not producer evidence.

M3 internal invariant codes occupy `RCA9101` through `RCA9104` for Discovery, Resolution, Lowering, and Analysis respectively, following #43's `RCA9xxx` internal-diagnostic allocation. M4 emission uses the separately registered `RCA9105` code and Emission stage. `RCA9001` through `RCA9005` remain reserved for the distinct M4 loader/protocol failures specified by #40 and are intentionally absent from the typed build-diagnostic registry.

Runtime lexical failures use the separate matching-version `RCA4000`, `RCA4001`, `RCA4002`, and `RCA4004` contract. They are intentionally absent from the build-diagnostic registry, and their producer ledger points to generated downstream assertions. The non-contiguous allocation is retained rather than renumbering a published-in-branch identifier.

Runtime parse failures use the adjacent append-only `RCA4100` through `RCA4105` contract for `UnexpectedToken`, `UnexpectedEof`, the retired Pratt-ambiguity classification `RCA4102`, `InvalidTokenSpan`, `GrammarMismatch`, and `DeclaredRejection` respectively. `DeclaredRejection` is the failure a declared rejection rule produces ([`../declared-rejections.md`](../declared-rejections.md)); it carries the rule's own opaque code beside this one. `RCA4102` was retired with the Pratt authoring surface ([`../declared-precedence.md`](../declared-precedence.md)): declared precedence decides every operator conflict in the LR tables, so no runtime ambiguity remains to classify, and the number is never reused. `LexicalError` preserves its originating `RCA400x` code rather than allocating a second classification. The separate runtime producer ledger cites generated public-seam assertions for ordinary failures and focused core-boundary assertions for invalid matching-version inputs.

M3-DIAG-004 verifies the private, line-oriented transport seam without claiming publication behavior. A black-box Cargo build-script fixture would require the public generation/publication surface that M3 deliberately does not provide; that publication-specific transport evidence is deferred to the M4 acceptance row.
